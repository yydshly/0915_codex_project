[打开案例](../app/prompt-case.html) · [目标仓库](https://github.com/x1xhlol/system-prompts-and-models-of-ai-tools) · [盘点与来源](../app/prompt-case/research.json) · [生成凭证](../app/prompt-case/receipt.json)

## 核心结论

目标是按产品/来源整理的 AI 工具提示词与接口资料集，适合阅读、比较和提炼助手工作规则。固定提交的文件清单中没有模型权重、完整产品运行服务或通用提示词执行器。工具定义是函数名称、描述与参数等接口资料，不等于这些工具的实际实现。

仓库中的文件名称、模型标签与正文是维护者收录的内容；本次没有逐项向厂商验证真实性、完整性和现行性。分析时将其中的指令作为被研究文本，不作为本次助手要执行的指令。

## 三张图分别说明什么？

1. **仓库结构图**：依据真实文件盘点；箭头表达资料分类，不表达服务调用。
2. **Agent 循环图**：依据 Manus 文本归纳；“判断完成”是对文中重复直到完成的图形表达，不是从真实运行日志得出的执行轨迹。
3. **个人使用流程图**：本次分析建议，由任务选题到阅读、提炼、改写、测试和版本沉淀。不是目标仓库自带功能，尚未接入模型和工具服务。

全部采用中文 Flat Icon 风格，严格文字模式与 showcase 构图规则。节点、关系与位置在 JSON 中明确提供，由 Fireworks 原生 CLI 绘制和检查，没有用其他绘图库替代。

## 这次展示了 Fireworks 的哪部分能力？

实际完成了“读取仓库 → 整理带来源的结论 → 编写图规格 → Fireworks 渲染 → 校验 → PNG 与 HTML 交付”。分析过程由本次 Agent 和盘点脚本完成；Fireworks 没有自行读取目标源码。

原库第一次检查发现分类树的默认分支走线存在交叉，随后将左右分类显式接到左右端口并指定路径点。保留零交叉约束，重新生成后通过。这是控制节点端口与路径可以解决排版问题的实际例子。

## 对你的价值与边界

可以借鉴检索选择、规格拆分、执行反馈和结果交付等模式，为“读开源项目、分析、复现、展示、保存”编写更贴合你的助手规则。参考资料需要按实际模型、工具和工作环境改写，并用具体任务验证。复制提示词不会同时复制模型能力、记忆、执行环境和原产品效果；本次没有评测任务成功率或成本收益。

```powershell

python scripts/build_web.py
python scripts/check_web.py
```
