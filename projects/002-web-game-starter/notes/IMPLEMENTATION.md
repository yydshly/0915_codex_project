# 能力展示的实现边界

## 展示设计

- 主界面直接展示上游实时场景，中文导航选择六项实验；每次只保留一个 iframe，避免多个三维场景同时占用 GPU。
- 六项分别为完整场景、角色动画、物理布娃娃、地面去重复、多层地形、游戏 UI。
- 每项都有操作提示、应用价值、实现原理和固定版本源码链接。
- 使用 URL hash 保存选择，刷新或分享本地地址可以回到同一实验。
- 提供重载、全屏和原版独立打开，窄屏下能力导航横向滚动。
- 模型处理中的等待由上游加载界面负责；外层加载提示仅表示正在打开页面，不声称资源加载或渲染成功。

## 复现方式

完整上游位于已忽略的 `upstream/`，固定到 `d5f62cb074b506697fb035c420415026bafbe792`。

独立 Python 启动器负责准备上游、安装锁定依赖、启动 Vite 和中文导览服务。仅监听本机回环地址，关闭启动器时回收其启动的 Vite 进程。

Node.js 22.15 默认无法直接运行上游安装阶段的 `.ts` 脚本。启动器仅向安装子进程添加 `--experimental-strip-types`，保留原有环境变量，不修改全局 Node 配置或上游源码。依赖下载使用本地缓存优先和有限超时，避免网络请求长期挂起。

六项原库实验的导览层不改原有游戏逻辑。后来新增的青屿庭院使用独立路由与功能目录，增量保存在 `patches/courtyard.patch`，启动器自动应用；原首页与实验入口保持可用。上游自身的安装脚本仅在其检出目录内链接项目技能，不安装到用户全局环境。

## 发布边界

研究结论网页已接入总仓库 GitHub Pages 构建流程：`app/` 是公开页面，`demo/capability-architecture.svg` 同时用作架构引导图与索引封面。元数据 `demo_url` 指向远端研究页。实时 3D 场景仍为本地展示，没有把指向本地服务的 iframe 或完整上游运行环境发布到公共网页。

上游完整源码未复制进本研究仓库的版本历史；第三方模型、音频和技能保留在上游检出中及其原有署名位置。当前上游根目录未发现统一 LICENSE 文件，后续分发整套源码或素材前需要明确授权范围。

## 验证记录

实际运行与检查结果记录于子项目 README。浏览器工具在跨源 iframe 内定位点击存在限制，因此具体上游控件的交互验证使用相同本地运行服务的独立原版页面；中文导览内的 iframe 已实际显示，导航和原版链接分别核对。临时检查页面在结束后关闭，保留用户的展示入口。

新增庭院直接在原运行环境的 `/courtyard` 打开，不套多重导航。设备状态均为模拟。虚拟向导乘悬浮盘按手工路线移动，复用原角色的待机和舞蹈动作；没有声称原素材包含行走动画。水面与庆祝粒子复用原库，设施造型和任务状态为本次新增。巡检完整流程、环绕镜头、夜景、重放、重置以及窄屏布局已在真实浏览器中确认。
