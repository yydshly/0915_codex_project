## 补充的重点

- 公平比较：具备工具的 AI 也能完成这些步骤；框架将其固定和自动化，不自动提升模型能力。
- 正确性标准：业务需求、权限规则和断言必须有独立依据。
- 证据强度：崩溃、可利用性、根因修复和补丁可合并是不同结论。
- 运行状态：没有 PoC 可能是任务中断，也可能是未发现，需检查执行记录。
- 漏报与成本：不能只统计发现数量；需有已知问题、正常对照和资源记录。
- 长期回归：动态补丁阶段运行已有测试，不自动为每个问题添加永久测试。
- 维护状态：所读版本明确不再维护；当前不继续投入深入研究，未来按需参考。

所有实现结论沿用 [固定版本来源](sources.md)，Web 与业务扩展为研究建议。图未表示执行过真实漏洞扫描。主流程属于概念闭环：Recon 可选、Judge 依赖流式模式，Patch 为单独命令，Triage 属于交互式跨轮次整理。
