# 能力与实现分析

本文基于固定提交的源码阅读，链接见[来源记录](sources.md)。未运行安全扫描。

## 1. 三种角色各自负责什么

| 角色 | 具体工作 | 不能据此推断什么 |
| --- | --- | --- |
| 大模型 | 理解代码、提出假设、构造输入、解释影响、修改代码 | 自己声称存在漏洞，不代表已证明 |
| Python 调度器 | 启动阶段、分配容器、解析输出、保存结果和重试 | 流程执行成功，不代表结论必然正确 |
| 运行环境与检测器 | 运行程序、输出 ASAN 诊断、执行构建和测试 | 检测到崩溃，不代表已证明远程代码执行等影响 |

框架把现有模型和工程工具组织成分阶段工作流程，没有训练一个新的安全模型。

## 2. 交互式审查与自动流水线

威胁模型描述资产、入口、信任边界和优先关注的威胁。静态扫描按区域阅读源码；分诊核实问题、合并同根因发现，并根据前提调整严重性。静态扫描与静态分诊不执行目标，主要产物是 Markdown 和 JSON。

自动流水线进一步构造输入并执行：

| 阶段 | 实现入口 | 具体机制 |
| --- | --- | --- |
| Build | `docker_ops.py`、目标 Dockerfile | 构建镜像，包含源码和带 ASAN 的程序 |
| Recon | `recon.py` | 可选地让模型分析不同输入模块，生成搜索区域 |
| Find | `find.py` | 模型在独立容器读源码、写输入、执行程序，提交 PoC 与复现信息 |
| Grade | `grade.py` | 从同一镜像新建容器，独立复现并输出分项判断 |
| Judge | `judge.py` | 流式模式下串行判断新漏洞、较好样例或重复发现 |
| Report | `report.py` | 分析影响并生成报告，再由独立评分阶段检查证据 |
| Patch | `patch.py`、`patch_grade.py` | 单独调用，生成补丁并进行多层执行检查 |

另有按 ASAN 签名聚类的事后去重命令。堆栈相同、模型认为同根因和已证明同一问题，是不同强度的判断。

## 3. 模型调用为什么绑定 Claude

`agent.py` 用异步子进程在容器中调用 Claude Code CLI，核心形式为 `claude -p --output-format stream-json`。默认工具是 Read、Write、Bash。

模型能自主操作文件和运行命令，是因为 CLI 提供了工具循环。只替换一个聊天 API 请求，不能自动保留这些能力。

调度器解析流式消息、提取结构化标签、保存 JSONL 记录，并利用 Claude 会话 ID 恢复可重试的失败。换模型运行层时，这些格式和恢复机制也需要重新对接。

## 4. 独立验证隔离了什么

Grade 从原始镜像重新创建容器，复制 PoC 到固定路径，不继承发现者修改过的程序、源码或环境。

需要精确理解上游“只有 PoC 跨边界”的表述：**迁移的实验文件是 PoC；验证提示仍接收复现命令、声称的崩溃类型和退出码等元数据。** 发现者完整推理和修改后的容器不会交给验证者。代码还把部分声称信息标为不可信数据，要求自行检查。

验证提示包含五项检查：

1. PoC 存在且非空。
2. 新容器运行三次，少于两次崩溃则失败。
3. 排除内存耗尽或超时。
4. 堆栈包含项目代码位置。
5. 检查崩溃类型一致性，对波动进行解释和降分。

Find 提示希望三次均崩溃；Grade 对部分可解释的波动留有判断空间。Grade 综合结论仍由模型读取执行证据后生成，Python 解析其结论。

## 5. 补丁检查为什么更具体

`patch_grade.py` 前三级直接运行命令并检查结果，无需模型给出通过票：

| 层级 | 依据 | 限制 |
| --- | --- | --- |
| T0 构建 | 补丁可应用，构建成功 | 只说明可构建 |
| T1 原输入 | 退出码为 0，输出不含 ASAN 标记 | 只检查原输入 |
| T2 现有测试 | 配置的测试命令成功 | 未配置则跳过，不自动补齐覆盖 |
| 再次攻击 | 新 Find 针对修复程序探索并检查触发证据 | 默认 50 轮，可关闭，有限搜索不能证明无绕过 |
| T3 风格 | 可选模型评分 | 仅供参考，不决定通过 |

前三级容器不需要模型凭据，并设置为无网络。再次攻击使用修补后环境的快照。失败证据反馈到下一次补丁尝试，迭代次数受预算约束。

**动态补丁流水线的 T2 运行现有测试，不自动为每个漏洞编写永久回归测试。** 静态 `/patch` 在目标有合适测试结构时尝试把对应测试放入候选修改，仍需执行验证。

## 6. 运行隔离和持久化

自动智能体运行在 gVisor 容器，网络出口由模型服务允许列表代理控制；不同阶段使用独立环境。隔离约束自主工具操作和目标执行的影响范围。

输入、结果、报告、补丁和交互记录被保存到结果目录。失败重试和检查点恢复支持长任务继续推进。运行预算、重试次数和搜索区域影响成本与效果。本次没有实测隔离配置或恢复行为。

## 7. 日志检测与响应

该分支研究“攻击行为是否已出现在日志中”。技能负责搜寻线索、分析影响、提出响应计划；自动流程包含 hunt 和独立 grade。

示例是带合成攻击活动的 Flask 应用。Hunt 容器拥有源码和只读日志，不含答案文件；Grade 拥有评分资料，并在重新初始化的应用上独立验证确认事件的 PoC。

接入真实日志、构造验证环境和对接告警平台仍需适配；示例不会自动执行响应处置。

## 8. 结果的证据强度

从弱到强可以理解为：模型认为可疑 → 源码路径解释 → 输入触发错误 → 独立环境复现 → 补丁通过原输入与现有测试 → 有限再次攻击未发现绕过。

最后一级依然不是安全证明。严重性还取决于部署方式、攻击者权限、真实入口和影响范围。
