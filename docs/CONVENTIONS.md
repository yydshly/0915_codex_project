# 项目管理约定

## 编号与顺序

- 目录格式：`projects/001-project-slug/`，编号范围 `001`–`999`。
- 编号代表收录顺序，首页始终按编号升序展示。
- 新项目取现有最大编号加一；编号不复用，也不根据研究状态重新排序。
- 已收录的项目需要停止研究时，将状态设为 `已归档`，保留目录与编号。
- `templates/project/` 是模板，不占用实际编号。

## 首页与详细记录

- 根 README：仓库摘要、项目索引、每个项目的预览图和一句话说明。
- 子项目 README：动机、运行方式、架构分析、实验过程和结论。
- 子项目 `notes/`：较长的研究过程与专题分析。
- 子项目 `project.json`：用于生成首页内容的唯一数据来源。
- 自动生成区域由 `PROJECT_INDEX` 和 `PROJECT_CARDS` 标记界定；其他首页内容可以手动编辑。

## 元数据字段

| 字段 | 说明 |
| --- | --- |
| `id` | 三位编号，与目录前缀一致 |
| `slug` | 小写英文、数字、短横线，与目录后缀一致 |
| `title` | 项目显示名称 |
| `summary` | 一句话说明项目内容和研究价值 |
| `upstream` | 上游仓库的完整 HTTPS 链接 |
| `status` | 待研究 / 研究中 / 已复现 / 已总结 / 已归档 |
| `tags` | 字符串数组，例如 `["Agent", "可视化"]` |
| `cover` | 子项目内已有图片的相对路径；没有图片时留空 |
| `demo_url` | 已可访问的完整 HTTPS 演示链接；未部署时留空 |

更新后执行：

```sh
python scripts/projects.py sync
python scripts/projects.py check
```

## 源码、依赖与许可

每个子项目独立管理依赖和锁文件，根目录不绑定统一前端框架。

默认使用上游链接、固定版本号和本地实验代码开展研究；需要本地完整检出时使用已忽略的 `upstream/`。未来若确实需要 Git submodule，单独按该项目需求接入。

引用第三方内容时保留来源、许可和署名。本次初始化不替研究者选择仓库许可证；第三方内容继续遵守各自的许可证。

## 图片

图片就近放在 `projects/<编号-名称>/assets/`，在子项目文档中解释图片展示的内容。封面通过元数据同步到总首页。大视频和大型数据文件使用外部存储链接。

## 上游链接显示名称

索引表与网页导航中的 GitHub 来源显示原仓库名称（从 URL 的仓库路径提取），不统一显示“GitHub”。非仓库来源显示站点域名，链接目标保持原地址。

## 多张引导图

可选字段 `guides` 接受非空列表，每项为 `path`（项目内图片路径）与 `caption`（文字说明）。设置后，总 README 和网站索引按顺序展示全部引导图；未设置时继续使用 `cover`。原有项目元数据无需修改。
